# 16 — حجم الـ Embeddings: الأرقام الحقيقية ⭐

> محسوب من ملفات `Backend/data/subjects/` فعلياً، لا تقديراً.

## 1. الخلاصة: **الحجم لا يمثّل مشكلة إطلاقاً**

| المدى | float32 | float16 |
|---|---|---|
| الثالث العلمي (الموجود اليوم) | **5.5 MB** | 2.7 MB |
| + الثالث أدبي | 10.9 MB | 5.5 MB |
| + الثاني علمي وأدبي | 21.9 MB | 10.9 MB |
| **كل الصفوف والمسارات (×6)** | **33 MB** | **16 MB** |

**لن تصل إلى جيجابايت. ولا حتى إلى 100 ميجابايت.**

## 2. كيف حُسبت

**الموديل:** `paraphrase-multilingual-MiniLM-L12-v2` → **384 بُعداً**.
متجه واحد = 384 × 4 بايت (float32) = **1,536 بايت**.

### عدد المقاطع الفعلي — الصف الثالث العلمي
| المادة | المقاطع | الوحدة |
|---|---:|---|
| احياء | 162 | صفحة |
| فيزياء | 229 | جزء درس |
| كيمياء | 235 | جزء درس |
| عربي | 48 | جزء درس |
| انجليزي | 17 | جزء درس |
| رياضيات | 779 | مقطع (63 ملفاً) |
| الوزاري | 2,265 | سؤال |
| **الإجمالي** | **3,735** | **مقطع** |

`3,735 × 1,536 بايت = 5.47 MB`

### سيناريوهات تقطيع أدق (worst case)
إجمالي نص المحتوى = **1,084,444 حرفاً ≈ 1.03 MB نصاً خاماً**.

| حجم المقطع | مقاطع الثالث العلمي | float32 | ×6 صفوف/مسارات |
|---|---:|---:|---:|
| 1200 حرف | 903 | 1.3 MB | 7.9 MB |
| 600 حرف | 1,807 | 2.6 MB | 15.9 MB |
| **300 حرف (دقيق جداً)** | 3,614 | 5.3 MB | **31.8 MB** |

**حتى بأدق تقطيع ممكن ولكل الصفوف: 32 ميجابايت.**

## 3. 🔴 العبء الحقيقي: الموديل نفسه، لا المتجهات

| العنصر | القرص | الذاكرة |
|---|---:|---:|
| فهارس FAISS (كل الصفوف) | **~33 MB** | ~33 MB |
| نصوص JSON | ~15 MB | ~15 MB |
| **موديل `MiniLM-L12-v2`** | **~470 MB** | **~500 MB – 1.1 GB** |
| FastAPI + PyTorch + التبعيات | — | ~400–600 MB |

> ⚠️ **هذا يفسّر فشل Render:** 512 MB من الذاكرة لا تكفي **لتحميل الموديل وحده**، ناهيك عن PyTorch. المشكلة لم تكن في المتجهات إطلاقاً.

**Hugging Face Spaces المجاني: ~16 GB قرص · ~2 GB ذاكرة** → يكفي، لكن بهامش ضيّق.

### تخفيف استهلاك الذاكرة
| الإجراء | التوفير |
|---|---|
| تثبيت الموديل في صورة Docker (لا تنزيل وقت التشغيل) | إقلاع أسرع بكثير |
| `torch` نسخة CPU فقط (`--index-url .../cpu`) | **~800 MB** |
| ONNX Runtime بدل PyTorch للاستدلال | ~300–400 MB |
| `float16` للمتجهات | نصف حجم الفهارس |

## 4. ✅ الحكم على الخطة المقترحة

**«كل مادة تعمل مثل الأحياء: وضع صفحة + وضع برومبت، الكتاب في ملف واحد، متجهات مبنية مسبقاً على القرص»**

### الحجم: ✅ ممكن تماماً — 33 MB لكل شيء.

### وهو **بالضبط** ما توصي به [ADR-012](08-decisions.md): بناء الفهارس مسبقاً وحفظها بدل بنائها في الذاكرة عند كل طلب.

```
tools/build_indexes.py            (يُشغَّل عند النشر فقط)
  لكل (grade, track, subject):
     texts, metas = extract_chunks(book)      ← الصيغة الموحّدة [11§4]
     emb = model.encode(texts)                ← مرة واحدة
     faiss.write_index(idx, f"indexes/{grade}_{track}_{subject}.faiss")
     json.dump({"texts":texts,"metas":metas}, ...)

عند الإقلاع:  faiss.read_index(...)           ← تحميل ملف، لا حساب
```

**المكسب:** يزول بناء الفهرس عند الطلب (مهلة 40 ثانية، سيمافور 2، يُعاد بناؤه بعد كل إقلاع) → [13§2](13-performance.md).

### الشرط المسبق: توحيد صيغة الكتب
لتعمل **كل** مادة بوضعَي الصفحة والبرومبت، يجب أولاً [ADR-011](08-decisions.md):
- الأحياء عندها **صفحات بلا دروس**
- الفيزياء/الكيمياء/العربي/الإنجليزي عندها **دروس بلا صفحات**

بدون توحيد الصيغة، "وضع الصفحة لكل المواد" **مستحيل** مهما فعلنا بالمتجهات — راجع [11§2](11-content-schema.md).
