# 30 — فهارس FAISS دائمة + تدقيق أداء الشات ⚡

**التاريخ:** 2026-08-27 · **ينفّذ:** [ADR-012](08-decisions.md) — «أكبر مكسب أداء منفرد»
**الاختبارات:** باك **146/146** ✅ · قياسات على خادم شغّال ببيانات المشروع الحقيقية

---

## 1. ما كان يحدث

```
طالب يسأل في وحدة لم يسألها أحد بعد
   ↓ يُحمَّل الكتاب  →  تُستخرج النصوص  →  🐌 تُضمَّن كلها  →  يُبنى الفهرس
   ↓ (بمهلة 40 ثانية، وقد تفشل)
   ↓ يُحفظ في قاموس بالذاكرة **بلا سقف**
   ↓ ❌ ولا يُحفظ على القرص أبداً ⇒ كل إقلاع = من الصفر
```

ثلاث علل في سطر واحد: **الطالب يدفع ثمن البناء** · **تسريب ذاكرة** · **ضياع كل شيء مع كل إعادة تشغيل** (وحاوية HF **تنام وتُعاد كثيراً** — [17](17-infrastructure-audit.md)).

## 2. الحل — ثلاث طبقات + إحماء

```
        🔥 عند إقلاع الخادم (خيط خلفي — لا يحجب الطلبات)
              ↓  يبني/يحمّل كل فهرس قد يُسأل عنه
   ┌──────────────────────────────────────────────┐
   │ 1. 🧠 ذاكرة (LRU بسقف 128)                    │
   │ 2. 💾 قرص  indexes/{بصمة}.faiss               │
   │ 3. 🔨 بناء (نادراً: محتوى جديد فقط)            │
   └──────────────────────────────────────────────┘
        ↓ طلب الطالب = قراءة فقط، **صفر بناء**
```

| الملف | الدور |
|---|---|
| `core/index_store.py` 🆕 | البصمة · كاش LRU · قراءة/كتابة القرص · `manifest.json` · إحصاءات |
| `core/warmup.py` 🆕 | يبني **نفس الشرائح** التي تستعملها المعالجات: الكتاب كاملاً + كل وحدة على حدة |
| `subjects/common.py` | `faiss_search` صارت: ذاكرة → قرص → بناء · و`build_index_sync` مشتركة |
| `api.py` | `lifespan` يشغّل الإحماء · `GET /health/indexes` لحالة الفهارس |

**البصمة الجديدة = SHA-1 على كل النصوص + اسم الموديل.**
> 🐛 القديمة كانت «الطول + أول 80 حرفاً + آخر 80» ⇒ **شريحتان مختلفتان بنفس الطول والحافتين تتشاركان فهرساً واحداً** — نتائج خاطئة صامتة. الجديدة تكشف تغيّر حرف واحد، وتُبطل كل الفهارس تلقائياً عند تبديل موديل التضمين.

## 5. برومبت وضع «سؤال» — تخفيف جراحي ✅

نفس السؤال، نفس المادة، نفس الاسترجاع — لكن:

| الوضع | «اشرح الاتزان الكيميائي» |
|---|---|
| **شرح** | إجابة كاملة ✅ |
| **سؤال** | «عذراً، هذه المعلومة غير متوفرة في المنهج المرفق» ❌ |

**تحقّقت أن الاسترجاع ليس السبب:** عند `top_k=3` كانت نصوص «الاتزان» **حاضرة فعلاً** في النتائج. السبب أن **برومت وضع «سؤال» أشدّ صرامة** فيرفض ما لا يجده منصوصاً حرفياً.

**القرار (المالك): تخفيف قليل جداً — والمنطق والأسلوب كما هما حرفياً.**

### التعديل — سطر واحد في ثلاثة ملفات، لا غير
الرفض كان في **تعليمات رسالة المستخدم** (لا في برومبت النظام)، بنصٍّ واحد مكرّر في
`physics.py` · `arabic.py` · `chemistry.py`:

```diff
- 2. … استخدم المعلومات المستخرجة للإجابة. إذا لم تكن الإجابة موجودة في المعلومات
-    المستخرجة، لا تخمن! قل: "عذراً، هذه المعلومة غير متوفرة في المنهج المرفق".
+ 2. … استخدم المعلومات المستخرجة للإجابة. وإن كان الموضوع موجوداً في المعلومات
+    المستخرجة لكن بصياغة مختلفة أو موزّعاً على أكثر من موضع، فاجمعه وأجب منه —
+    هذا استخدامٌ للنص لا تخمين. أما إذا كان الموضوع نفسه غير موجود في المعلومات
+    المستخرجة، فلا تخمن! قل: "عذراً، هذه المعلومة غير متوفرة في المنهج المرفق".
```

**ما بقي كما هو تماماً:** البند 1 (التحية) · البند 3 (قواعد المعادلات الكيميائية) ·
برومبتات النظام كلها · **نفس جملة الرفض حرفياً** · أوضاع شرح/تلخيص/وزاري · المنطق والاسترجاع.
**الإضافة الوحيدة:** السماح بجمع المعلومة من النص حين تكون مبعثرة أو بصياغة مغايرة.

### التحقق بعد التعديل (خادم حيّ)
| الحالة | النتيجة |
|---|---|
| «اشرح الاتزان الكيميائي» (كيمياء) | ✅ أجاب — كان يرفض |
| «ما هي نظرية بوهر؟» (فيزياء) | ✅ أجاب |
| «ما هو المفعول المطلق» (عربي) | ✅ أجاب |
| «ما هي عاصمة البرازيل؟» | 🚫 **رفض** بنفس الجملة |
| «اشرح نظرية الأوتار الفائقة» | 🚫 **رفض** بنفس الجملة |
| «السلام عليكم» | 👋 ردّ بلطف كمعلّم |

**الحارس لم يضعف:** ما هو خارج المنهج ما زال يُرفض بنفس النص.

## 6. التشغيل

```bash
cd Backend && python -m uvicorn api:app --host 0.0.0.0 --port 8000
```
الفهارس تُبنى تلقائياً عند الإقلاع. لمتابعة الحالة:
```bash
curl -s localhost:8000/health/indexes
```
`indexes/` مُضاف إلى `.gitignore` — يُعاد بناؤه ذاتياً على أي خادم جديد (9.8s مرة واحدة).
**عند تعديل محتوى مادة:** البصمة تتغيّر ⇒ يُبنى فهرسها الجديد تلقائياً في الإقلاع التالي. لا خطوة يدوية.
