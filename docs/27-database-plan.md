## 2. Firestore أم PostgreSQL؟

القرار لا يُحسم بـ«أيهما أفضل» بل بحالتك أنت:

| المعيار | حالتك | Firestore | PostgreSQL |
|---|---|---|---|
| **التوثيق** | تحتاج جوجل + بريد + زائر | ✅ Firebase Auth جاهز ومجاني | ❌ تبنيه أو تستأجر Supabase |
| **الإشعارات** | «منحة جديدة» → إشعار | ✅ FCM مدمج ومجاني | ❌ خدمة منفصلة |
| **الباك على HF Spaces** | **ينام ويُعاد تشغيله كثيراً** ([17](17-infrastructure-audit.md)) | ✅ HTTP بلا اتصالات دائمة — الإقلاع البارد لا يكلّف شيئاً | ⚠️ Connection pool مع حاوية تنام = وجع مستمر |
| **شكل الاستعلامات** | مستخدم واحد · محادثاته · نتائجه · قائمة منح | ✅ مفتاح→مستند، بلا Joins | 🟰 يعمل، لكن قوته (Joins/تجميعات) لا تُستعمل |
| **الأوفلاين في التطبيق** | الطالب اليمني — إنترنت متقطّع | ✅ كاش مدمج (وأنت أصلاً على Hive) | ❌ تبنيه بنفسك |
| **البحث النصي في المحتوى** | ❌ غير مطلوب أصلاً | لا يدعمه | يدعمه |
| **الفاتورة عند 2,500 طالب** | §6 | **$0** | استضافة + صيانة |

> 🔑 **السبب الحاسم:** أقوى ما في PostgreSQL (Joins، تجميعات، بحث نصي) **لن تستعمله** — لأن المحتوى الثقيل (الكتب والوزاري) قرارُه محسوم: يبقى **JSON + FAISS** ولا يمر بقاعدة بيانات أصلاً ([03§2](03-data-strategy.md) · [ADR-001](08-decisions.md)). أما ما يحتاج قاعدة بيانات فعلاً — مستخدم، محادثاته، نتائجه، منح — فكله «اقرأ مستنداً بمفتاحه». هذا بالضبط ما صُنعت له Firestore.

**خط الرجعة (إلزامي):** كل وصول للبيانات خلف **طبقة Repository** — تماماً كما فعلنا في `ChatRepository` و`TutorContentRepository`. لو احتجت الهجرة يوماً، تُبدَّل طبقة واحدة لا التطبيق.

**متى تعيد النظر؟** إن صرت تحتاج تقارير تحليلية معقّدة للوحة (تقاطعات ومتوسطات عبر آلاف السجلات). الحل حينها **ليس** ترك Firestore، بل تصدير `stats/` إلى BigQuery.

➡️ **[ADR-003](08-decisions.md) يتحوّل من 🟡 مقترح إلى 🟢 معتمد.**

## 3. الصور — قرارك صحيح، وهذه تبعته

**المعتمد (منفّذ فعلاً — [24§5](24-image-input.md)):**

```
📷 الطالب يصوّر → ضغط في التطبيق → base64 مع الطلب
   ↓ الخادم: Gemini يستخرج النص، ثم req.image_base64 = None فوراً
   ↓ لا قرص، لا لوجات، لا Storage
💾 الصورة تبقى في جوال الطالب: ApplicationDocuments/chat_images/{uuid}.jpg
   والمحفوظ في Hive هو **المسار** فقط
```

**ما يُرفع إلى السحابة مع المحادثة: النص المستخرج فقط، لا الصورة.**

> ⚠️ **التبعة الوحيدة — اقبلها بوعي:** طالب يغيّر جواله أو يعيد تثبيت التطبيق تعود له محادثاته **بلا صورها** (الفقاعة تعرض «الصورة لم تعد متاحة»، وهو سلوك مُنفَّذ ومختبَر). المقابل: خصوصية كاملة + صفر تكلفة تخزين + صفر مخاطر محتوى مرفوع. **الصفقة رابحة** — والصورة أصلاً استُهلكت في سؤال واحد.

**Storage يُستعمل في موضعين فقط لا ثالث لهما:**
1. صورة الملف الشخصي `avatars/{uid}.jpg` (مضغوطة 300px) — [v3 §5.9]
2. صور المنح والبانرات التي **يرفعها الأدمن** من اللوحة (≤200KB)

## 4. المخطط كاملاً الآن، والتنفيذ بشرائح ⭐

**لا تحدد لي المعمارية الكاملة من جديد — هي محدّدة أصلاً** في [v3 §2](../masar_platform_v3.md) و[07-data-model](07-data-model.md). Firestore **بلا مخطط ثابت (schemaless)**: إضافة `results/` أو `saved_answers/` بعد شهر لا تكلّف شيئاً ولا تمسّ ما قبلها.

لكن **أربعة أشياء تكلفتها باهظة لو أُجّلت** — تُبنى مرة واحدة وصح في الشريحة الأولى:

| # | الشيء | لماذا الآن تحديداً |
|---|---|---|
| 1 | **`uid` بديلاً لنظام الأكواد** | كل قسم لاحق (نتائج، محفوظات، حصص، إشعارات) يُعنون بـ`uid`. بناؤه لاحقاً = ترحيل بيانات الطلاب |
| 2 | **قواعد الأمان + اختباراتها** | فخ `{doc=**}` يجعل الطالب يرقّي نفسه أدمن ([07§2](07-data-model.md)). تُكتب مرة، وتُختبر بخمسة اختبارات إلزامية |
| 3 | **بروتوكول `meta.version`** | كل قسم قادم (منح · خدمات · بانرات · أسئلة مقترحة) يركب عليه. لو أضفتها بلا كاش النسخة، أعدت السباكة في كل شاشة ([v3 §12](../masar_platform_v3.md)) |
| 4 | **حصة يومية (Quota)** | 🔴 **حرج:** اليوم بوابتك للـAI هي «الكود». يوم تحذفه بلا حصة، تصير فاتورة الذكاء الاصطناعي مفتوحة للعالم. الحصة تنزل **في نفس شريحة التوثيق لا بعدها** ([ADR-008](08-decisions.md)) |

كل ما عدا هذه الأربعة **يُضاف متى وصلت لقسمه**.

## 5. الشرائح بالترتيب

### شريحة أ — العمود الفقري (توثيق + أمان + حصة) 🔴 الأولى
```
users/{uid} { name, email, grade, track, photo_url, role:"student"|"admin",
              created_at, fcm_token, is_anonymous,
              settings:{dark_mode, font_size, auto_tts, robot_enabled} }
config/meta          { version, content_version, updated_at }
config/app_settings  { min_version, maintenance_mode, sections_enabled{}, quota_ask, quota_light }
usage/{uid}_{yyyy-mm-dd} { asks, lights }        ← كتابة واحدة/طالب/يوم
```
- Firebase Auth: بريد+كلمة · Google · **زائر (anonymous)** بحد 5 أسئلة
- الباك: التحقق من **Firebase ID token** بدل `verify_code` — و`/verify-access` و`codes.json` و`auth.py` تُحذف
- **انتقال آمن:** الباك يقبل التوكن **والكود** معاً لفترة، ثم يُسقط الكود
- ⚠️ الصف والمسار ينتقلان من `UserSession` المحلي إلى `users/{uid}` — وهما موجودان في التطبيق فعلاً

**القبول:** طالب جديد يسجّل → يفتح التعليم → يسأل → يُحتسب في حصته · طالب يحاول كتابة `role:"admin"` → **يُرفض**

### شريحة ب — المحادثات (قسم التعليم)
```
users/{uid}/conversations/{convId}
  { title, subject, mode, grade, track, branch, scopeKey,   ← ★ نطاق [15]
    messages:[{role, text, refs[], ts}], created_at, last_updated }
```
- **Hive يبقى المصدر الأول للعرض** (سريع + أوفلاين). Firestore نسخة سحابية.
- **الكتابة:** بعد كل رد ناجح، `set(merge:true)` بالمحادثة كاملة، fire-and-forget. بلا نت → `pending_sync` في Hive ويُرفع عند عودة الاتصال.
- **السحب مرتين فقط:** جهاز جديد، أو زر «🔄 استعادة محادثاتي». **لا Streams ولا مزامنة دورية إطلاقاً** — هذا ما يحمي الفاتورة.
- ★ `scopeKey` **إلزامي في المستند**، وإلا رجعت المحادثات المستعادة بلا نطاق فاختلطت الصفوف والمواد.
- الصور: يُرفع النص المستخرج لا الصورة (§3).

### شريحة ج — اختبر نفسك 🧠 (أصغر بصمة على القاعدة — ابدأ بها بعد التعليم)
```
config/aptitude_test        { questions[15] }          ← تُحرَّر من اللوحة
users/{uid}/results/{id}    { type:"quiz"|"aptitude", subject, unit, score, total,
                              wrong_topics[], report_text, created_at }
```
- **أسئلة اختبار المادة تُولَّد بالـAI ولا تُخزَّن** ([03§5](03-data-strategy.md)) — كتابة واحدة فقط لكل اختبار.
- «الحلقة الذهبية»: نقاط الضعف → زر «اشرح لي 📚» يفتح شات المادة بالسؤال جاهزاً.

### شريحة د — المنح + لوحة التحكم 🎓
```
scholarships/{id}          { name, country, cover_url, short_desc, about,
                             requirements[], how_to_apply, open_date, close_date,
                             funding_type, enabled, order, updated_at }
scholarship_prompts/{id} 🔒 { assistant_prompt }        ← الباك فقط (Admin SDK)
banners/{id} · services/{id} · suggested_questions/{id}
```
- كل كتابة من اللوحة على `scholarships/` أو `services/` أو `banners/` أو `config/` **ترفع `meta.version`** ⇒ التطبيق يلتقطها في الإقلاع التالي ([06](06-admin.md)).
- 🔒 `assistant_prompt` في **مجموعة موازية** لا داخل مستند المنحة — وإلا قرأه الطالب.
- إشعار «منحة جديدة» عبر FCM topic.
- اللوحة (Flutter Web منفصل) مسموح لها Streams — عدد الأدمن ضئيل.

### مؤجَّل بوعي
`saved_answers/` · `stats/daily`.
**دور المعلم** ([33](33-teacher.md)): القسم يعمل بلا نمذجةٍ جديدة — محادثاته تسكن `users/{uid}/conversations` نفسها بمفتاح نطاقٍ يحمل الأداة، وبرومبتاته في `teacher_prompts/{tool}` 🔒 (الباك وحده). و**دورٌ في الحساب** لم يُضف بعد.

## 6. ⭐ سياق المحادثة وحجم التخزين — ثلاثة أرقام لا تخلط بينها

| # | الرقم | يؤثر على | كان | صار |
|---|---|---|---|---|
| 1 | **ما يراه الموديل** (`chat_history`) | فاتورة الـAI (التوكنات) | 6 | **6** (بلا تغيير) |
| 2 | **ما يُرسل على الشبكة** | سرعة الطلب على إنترنت ضعيف | **10** ⚠️ | **6** |
| 3 | **ما يُخزَّن** (Hive/Firestore) | **حجم قاعدة البيانات** | المحادثة كاملة | المحادثة كاملة |

> 🔴 **الخلط الشائع:** تقليل `chat_history` **لا يصغّر قاعدة البيانات إطلاقاً** — القاعدة تخزّن المحادثة كاملة. الرقمان مستقلان تماماً، ولكل واحد علاجه.

### 6.1 ما أُصلح في الرقم ٢
الفرونت كان يرسل **10 رسائل كاملة بلا قصّ**، بينما **كل** معالج في الباك يستعمل آخر **6** (`[-6:]`) — أي أن 4 رسائل ترحل عبر الشبكة في كل طلب ثم تُرمى. مع رد شرح يبلغ 4,000 حرف، هذا هدر ملموس على شبكة ضعيفة.

**الآن:** الفرونت يرسل 6، وكل رسالة مقصوصة عند **1,500 حرف** (نحتفظ بالبداية: فيها الموضوع، والذيل تفاصيل وأمثلة) ⇒ سقف السياق **9,000 حرف** بدل ~40,000. ([ADR-005](08-decisions.md))

**والرقم صار مصدراً واحداً:** كان `[-6:]` مكرراً في **17 موضعاً عبر 7 ملفات** — أي موضع يُنسى يخالف البقية. الآن `HISTORY_LAST_N` في `config.py`، ويحرسه اختبار يرفض عودة أي رقم مبعثر.

| الطبقة | السقف |
|---|---|
| الفرونت (`ChatController`) | 6 رسائل × 1,500 حرف |
| `models.py` (سقف دفاعي على ما يصل) | 8 رسائل × 2,000 حرف — أوسع كي لا يُكسر عميل قديم |
| المعالجات (ما يراه الموديل) | `HISTORY_LAST_N = 6` |

### 6.2 حجم القاعدة — الخطر الحقيقي 🔴

هنا يكبر التخزين فعلاً، وحسابه يجب أن يكون بالبايت لا بعدد الرسائل:

> ⚠️ **الحرف العربي في UTF-8 = بايتان.** رد بـ3,000 حرف ≈ **5.4 كيلوبايت** لا 3.

| البند | التقدير |
|---|---|
| محادثة نموذجية (6 أسئلة + 6 ردود) | ~18 KB |
| طالب نشط خلال فصل (15 محادثة) | ~270 KB |
| **2,500 طالب** | **~675 MB من 1 GB مجاني** |

**بهامش ضيق — والسنة الثانية تتجاوزه.** لذلك تُوضع السياسة **من اليوم** (إضافتها لاحقاً = ترحيل بيانات):

| # | السياسة | لماذا |
|---|---|---|
| 1 | **سقف بايت للمستند: 200 KB** — تُقص أقدم الرسائل من **النسخة السحابية فقط** (Hive يحتفظ بها) | حد Firestore للمستند 1 MiB، والقصّ بالبايت لا بعدد الرسائل بسبب UTF-8 |
| 2 | **آخر 30 محادثة لكل طالب تُزامَن** — الأقدم يبقى على الجهاز | يقصّ التخزين إلى النصف تقريباً |
| 3 | **تنظيف تلقائي (Firestore TTL):** محادثة بلا نشاط 6 أشهر تُحذف سحابياً | الفصل الدراسي انتهى |

**النتيجة بعد السياسة:** ~2,500 × 30 × 18KB بحد أقصى نظري، وواقعياً **≈ 300–400 MB** — داخل المجاني بهامش مريح.

## 7. التوثيق بالتفصيل (شريحة أ)

```
Google         → الاسم والبريد والصورة من الحساب ⇒ يدخل مباشرة
بريد + كلمة سر → الاسم + البريد + كلمة السر
                 ↓ إرسال رابط تحقق (sendEmailVerification)
                 ↓ شاشة «تحقّق من بريدك» + زر «أعد الإرسال» (بمهلة 60 ثانية)
                 ↓ لا يدخل التطبيق قبل emailVerified == true
نسيت كلمة السر → sendPasswordResetEmail ⇒ رابط من Firebase
زائر           → anonymous · 5 أسئلة ثم دعوة للتسجيل
                 ↓ عند التسجيل: linkWithCredential ⇒ محادثاته تنتقل معه
```

| نقطة | القرار |
|---|---|
| رابط تحقق أم OTP؟ | **رابط تحقق** — Firebase يوفّره مجاناً وجاهزاً. OTP بالبريد يحتاج قالباً وخادم بريد وكوداً إضافياً بلا مكسب أمني هنا |
| قالب الرسالة | يُعرَّب من Firebase Console (الاسم والمرسِل ونص الرسالة) |
| البريد غير المتحقَّق | يُنشأ مستخدمه في Auth لكن **لا يُنشأ `users/{uid}`** ولا تُصرف له حصة إلا بعد التحقق |
| ⚠️ فخ | الحساب غير المتحقَّق يظل قائماً في Auth ويحجز البريد. تُضاف مهمة تنظيف دورية للحسابات غير المتحقَّقة بعد 7 أيام |

## 9. الفاتورة عند 2,500 طالب نشط (1,500 طلب/يوم)

| البند | يومياً |
|---|---|
| قراءة `config/meta` عند كل فتح (فتحتان/طالب) | ~5,000 قراءة |
| كتابة المحادثة بعد كل رد | ~1,500 كتابة |
| عدّاد الحصة (مستند واحد/طالب/يوم) | ~2,500 كتابة |
| الباك يقرأ `config` بكاش 5 دقائق | 288 قراءة |
| **الإجمالي** | **~5,300 من 50,000 قراءة · ~4,000 من 20,000 كتابة** |

**= $0 شهرياً، وبهامش 4–5 أضعاف.** ما يكلّفك فعلاً هو الذكاء الاصطناعي ($40–70 شهرياً) لا قاعدة البيانات.
